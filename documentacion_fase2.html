1. Resumen del sistema Secciones 2 y 14

Room Master resuelve la operación de la recepción de un hotel: conocer el estado de cada habitación (libre, ocupada o en limpieza), registrar ingresos y salidas, reubicar huéspedes, cobrar según el piso y la duración de la estadía, y consultar indicadores de ocupación y recaudación. En esta segunda parte el sistema pasó de un único archivo con datos en memoria a una aplicación modular que conserva la información entre ejecuciones.

3. Estructuras de datos Ítem 15.b

Cada estructura se eligió por una propiedad concreta que el dato necesita. La siguiente figura muestra cómo se combinan dentro del registro de un huésped. 

# huespedes.py · realizar_checkin()
datos_huesped = {                                    # DICCIONARIO: registro con campos por nombre
    "identidad": (dni, nombre),                    # TUPLA: no cambia nunca
    "dias": dias,                                  # int
    "ubicacion": [piso, habitacion, num_comercial]  # LISTA: cambia en el swap
}
lista_huespedes.append(datos_huesped)                # lista de diccionarios

3.1 Conjuntos (set)

Uso 1 · Evitar DNI duplicados

Dónde: huespedes.validar_dni

Se arma un conjunto con los DNI de los huéspedes alojados y se pregunta si el nuevo DNI pertenece.

dnis_registrados = set()
for huesped in lista_huespedes:
    dnis_registrados.add(huesped["identidad"][0])
while dni_nuevo in dnis_registrados:
    ...  # informa y pide otro DNI

Por qué: un conjunto no admite repetidos y la pertenencia (in) se resuelve por hash, en tiempo constante promedio, sin recorrer la lista elemento por elemento.

Uso 2 · Comparar información

Dónde: reportes.reporte_habitaciones_libres

Se construyen dos conjuntos de números de habitación y se operan:

todas    = {101, 102, 103, 201, 202, 203}
ocupadas = {102, 201}
libres   = todas.difference(ocupadas)   # diferencia
comunes  = todas.intersection(ocupadas)   # intersección

Por qué: la pregunta "¿qué habitaciones no están ocupadas?" es exactamente una diferencia de conjuntos. La intersección asegura que solo se informen ocupadas que existen en el hotel actual.

3.2 Tuplas (tuple)

Qué representaDónde se usaPor qué una tupla
Identidad del huésped
(dni, nombre)		realizar_checkin; se lee en búsquedas, check-out y reportes.El DNI y el nombre se cargan una vez y no deben modificarse durante la estadía. La tupla es inmutable: un intento de cambiar identidad[0] produce un error en lugar de alterar el dato. Además, agrupa dos valores que siempre van juntos.
Coordenadas de habitación
(piso, habitacion)		obtener_indices_matriz, solicitar_habitacion_libreUna función devuelve dos valores relacionados en un solo retorno, que se desempaqueta: piso, hab = obtener_indices_matriz(201).
Destino del swap
(piso, habitacion, numero)		pedir_habitacion_destino, mover_huespedViaja como un único valor entre funciones; (-1, -1, -1) indica cancelación.
Por qué la ubicación no es una tupla La ubicación del huésped sí cambia (en el swap se actualizan piso, habitación y número), por eso es una lista. La decisión tupla/lista sigue una regla simple: lo que no debe cambiar es tupla, lo que puede cambiar es lista.

4. Persistencia Ítem 15.c

La información se guarda exclusivamente en archivos (Sección 12.2). Cada formato cumple un propósito distinto: JSON para el estado del hotel y texto plano para el historial de facturación.

4.1 Respuesta a las preguntas de la consigna

PreguntaRespuesta
¿Qué información se almacena?Las dimensiones del hotel, el esquema de tarifas por piso, los huéspedes alojados (identidad, días y ubicación) y el historial de check-outs realizados.
¿En qué archivo?hotel_data.json (estado del hotel), facturacion.txt (bitácora) y facturacion.csv (exportación).
¿Qué se guarda en JSON?El estado actual: pisos, habitaciones, huespedes y el diccionario de tarifas ({"1": 10000.0, ...}). Es información estructurada que se sobrescribe completa en cada guardado.
¿Qué se guarda en texto?Una línea por cada check-out con 6 campos delimitados por ;: DNI, nombre, habitación comercial, piso, noches y total cobrado. Es información histórica en modo agregado ("a") que nunca se reescribe.
¿Cómo se recupera?El JSON se lee al iniciar y reconstruye el hotel (ver 4.3). La bitácora se lee para mostrar el historial y para generar el CSV (ver 4.4).

Cuándo se escribe: al terminar la configuración inicial, después de cada check-in, check-out, swap, restablecimiento y redimensionamiento, y al salir con la opción 0.

Cómo: json.dump(datos, archivo, ensure_ascii=False, indent=4) en modo "w" y codificación UTF-8. ensure_ascii=False conserva tildes y eñes legibles (Muñoz, no Mu\u00f1oz).

Claves numéricas en JSON: El formato JSON serializa las claves de los objetos como cadenas ("1", "2"). Al deserializar con cargar_datos_hotel(), el sistema convierte las claves a enteros (int(piso)) para permitir el acceso nativo numérico matriz_tarifas[piso].

Conversión Python ↔ JSON:

PythonJSONAl leer
dictobjetodict
listarreglolist

str / int / floattexto / númeroigual
Detalle técnico: la tupla en JSON JSON no tiene tipo tupla, así que json.dump guarda identidad como arreglo y json.load lo devuelve como lista. Como el sistema siempre lee la identidad por índice ([0] DNI, [1] nombre), el comportamiento es idéntico antes y después de reiniciar. Si se quisiera mantener la inmutabilidad también después de cargar, basta con huesped["identidad"] = tuple(huesped["identidad"]) al recuperar los datos.

5.2 Estructura completa: try / except / else / finally

# archivos.py · guardar_datos_hotel()
try:
    archivo = open(nombre_archivo, "w", encoding="UTF-8")
    json.dump(datos, archivo, ensure_ascii=False, indent=4)
    guardado = True
except PermissionError:            # específica primero...
    print("ERROR. No tiene permisos para acceder al archivo.")
except (ValueError, TypeError):
    print("ERROR. El archivo contiene registros incorrectos.")
except OSError as error:            # ...la general al final
    print("ERROR al trabajar con el archivo:", error)
else:                               # solo si no hubo excepción
    print("Escritura finalizada correctamente.")
finally:                            # siempre: cierra el archivo
    if archivo != None:
        archivo.close()

Orden de los except

PermissionError es subclase de OSError. Si OSError fuera primero, el mensaje específico nunca se mostraría.

else

Separa el camino exitoso del código que puede fallar: el mensaje de éxito no se imprime si la escritura falló.

finally

Garantiza que el archivo se cierre aunque json.dump falle a mitad de la escritura.

5.3 Errores prevenidos sin try

Las conversiones como int(dato) o float(dato) podrían lanzar ValueError. En lugar de envolverlas en try, el dato se valida antes con una expresión regular en validar_generico, que pide reingresar hasta que el formato sea correcto. Cuando se llega a la conversión, el error ya es imposible.

RiesgoPrevención
int("abc") → ValueErrorPATRON_NUMERO_VALIDO = r"^\d+$" solo deja pasar dígitos.
hotel[5][0] en un hotel de 2 pisos → IndexErrorhabitacion_existe(matriz, piso, hab) verifica los límites antes de acceder.
División por cero en el porcentaje de ocupaciónif total_habitaciones > 0 antes de dividir.
Huésped inexistenteLas búsquedas devuelven [] o -1 y se informa al usuario.

6.3 Guía para la defensa

La Sección 9 indica que el docente puede elegir cualquier prueba y preguntar qué comprueba, por qué se eligió, qué se espera y qué pasaría si cambiaran los datos.

Anexo B · Ciclo de vida de una habitación Sección 13

Cada celda de la matriz es un pequeño autómata con tres estados. Solo las operaciones del menú pueden cambiarlo, y cada cambio se guarda en el JSON.

TransiciónFunciónCondición previa validada
L → O (check-in)realizar_checkinLa habitación existe y está libre; DNI válido y no repetido; días > 0.
O → S (check-out)realizar_checkoutHay huéspedes y el DNI corresponde a un huésped alojado.
O → L / L → O (swap)mover_huespedHay huéspedes, hay habitaciones libres y el destino existe y está libre.
S → L (restablecer)restablecer_limpiezaLa habitación existe y está en estado S.
Por qué existe el estado S En un hotel real, una habitación recién desocupada no se puede entregar hasta limpiarla. El estado intermedio impide que el check-in la ofrezca como libre y obliga a una confirmación explícita.

Anexo C · Instrucciones de ejecución Sección 16

Pasos para ejecutar el sistema en otro equipo.

Requisitos

  • Python 3.8 o superior (probado en Python 3.14 sobre Windows).
  • No se necesitan librerías externas para el sistema. pytest es opcional.

Pasos

# 1. Obtener el proyecto
git clone https://github.com/lucassebastianramos/room-master.git
cd room-master

# 2. Ejecutar el sistema
python main.py

# 3. Ejecutar las pruebas sin instalar nada
python tests.py

# 4. (Opcional) Ejecutar las pruebas con PyTest
python -m pip install pytest
python -m pytest tests.py -v
Nota para Windows Si el comando pytest no se reconoce, usar python -m pytest. Ocurre porque pip instala el ejecutable en una carpeta que no está en el PATH.
